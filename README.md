# Pixel

这是 [wuzf/2fa](https://github.com/wuzf/2fa) 项目的主题，不能单独运行：需要先部署 2FA（2.0.0 或更高版本），再在 **设置 → 外观与主题 → 主题 → 社区主题** 中安装。

Pixel 是为 2FA 制作的完整前端主题，以像素纸张、硬边轮廓和山谷与前哨像素景观呈现复古游戏氛围，布局是 RPG 背包：账户是物品格子，顶部是分类页签，每个格子直接显示服务、账户、当前验证码、下一个验证码和剩余秒数，点击即可复制，不需要再打开详情面板。账户、验证码和账户操作全部使用 2FA 主机 SDK。

当前版本为 **Pixel 1.0.0**，主题 ID 为 `pixel-for-2fa`。

## 安装与升级

需要支持 `themeApiVersion: 2`、`kind: app`、`sdkApiVersion: 1`、`sdk.clock.now()` 及下述挂载协议的 2FA 主机。仅支持 v1 CSS/layout 的旧主机无法安装；普通应用主题的启用还受主机版本的审核/资源完整性门槛约束，不提供绕过开关。

```sh
npm ci
npm run build
```

产物为 `dist/2fa-theme.zip` 与 `dist/2fa-theme.zip.sha256`。在主机“外观”中导入 ZIP，核对主题身份和信任提示，预览后应用。升级时导入新版本并通过同一外观编辑器应用，主机负责保留可兼容的配置和原主题回滚记录。不要手工替换某个 JS/CSS 文件，也不要自行清除主机离线缓存。

若主题启动失败，使用主机安全模式与外观恢复入口切回官方主题。

## 使用与配置

- 账户：当前码和下一码复制、真实 HOTP 状态、二维码、URI、共享链接、添加/编辑/删除。
- 集合：搜索与服务选择器始终可见，服务显示全部/各组及账户数；“视图”收纳分组/平铺、组排序和账户排序；账户始终以卡片显示。服务数量增加不会生成多行按钮。
- 管理：账户与数据、工具、设置、应用与恢复四组按需展开；扫码、导入/导出、备份、六项工具、四种同步、安全/偏好/自定义代码、外观、安全恢复、隐藏账户、离线队列、扩展、PWA、快速OTP均可到达。工具和同步优先使用宿主聚合页，聚合不可用时保留原子入口与禁用原因。
- HOTP：剪贴板与服务端预留分别展示，过滤账户后在途状态仍可见。核对仅调用主机对账；恢复请求交给主机资格检查，不自动复制或再次预留。
- 操作反馈：复制等结果显示在当前视口底部，长页中无需回到顶部查看；成功提示4秒，失败或部分成功8秒。提示不阻挡点击，HOTP待恢复操作仍保留在操作区。
- 明暗与语言：跟随主机 light/dark/auto 和 15 种语言，主机功能文案使用主机词条，自有短文案提供对应翻译。管理中的“偏好设置”打开唯一宿主偏好入口，“主题设置”打开外观编辑器；旧偏好深链接仍可用。
- 动效：none、flow、flip、spotlight 仅改变显示；复制前同步结束过渡，始终传回 SDK 原始票据。支持减少动态效果、键盘菜单/卡片导航与强制颜色模式。

主题设置位于主机外观编辑器：

| 配置           | 值                            | 默认          |
| -------------- | ----------------------------- | ------------- |
| `landscape`    | `valley` / `outpost` / `none` | `valley`      |
| `density`      | `comfortable` / `compact`     | `comfortable` |
| `accent`       | `green` / `violet` / `rose`   | `green`       |
| `pixelChinese` | `true` / `false`              | `true`        |

站点名称、说明、Logo、背景、登录文案和页脚采用主机品牌配置，应用图标由主机统一维护。本地字体有系统字体回退；不声称像素字体覆盖全部语言字形。

## 开发与验证

```sh
npm run dev
# http://127.0.0.1:4197
npm test
npm run format:check
```

开发壳明确标注“合成账户/合成时间”，只记录主机命令和模拟复制反馈，不写实际剪贴板、不保存账户、不执行真实 HOTP 事务。`dev/`、测试、静态 `design-preview.html` 均不会进入主题包。安装入口只从传入的 SDK 读取账户，不会拿示例账户回退。

可选设置 `HOST_ROOT` 指向支持 v2 的主项目源码，执行实际 emitted SDK 集成测试以及正规包验证。仓库运行和构建不依赖开发者的私有绝对路径：

```powershell
$env:HOST_ROOT = 'D:/projects/2fa'
npm test
npm run test:host
```

未设置 `HOST_ROOT` 时，实际主机集成测试明确标记 skipped，其余合成行为/完整资产清单/哈希/可复现打包测试仍执行。主机测试使用合成密钥和可控网络/剪贴板，验证真实 SDK、OTP 引擎、HOTP 命令、URI/link、真实编辑弹窗和 15 语言；不等同于浏览器权限、相机、OAuth 或真实服务端写入验收。

相机授权、云端 OAuth/同步、操作系统 PWA 安装和 Safari 尚未测试。

## 公共集成协议

```js
export function mount({ root, sdk, appearance, signal }) {
  return { update(nextAppearance) {}, unmount() {} };
}
```

`appearance` 使用主机冻结的 `{kind,packageId,package,revision,settings,branding,baseUrl,files}`。动态品牌图片使用匿名跨源请求以支持隔离预览；包字体和景观是相对本地路径。主题仅管理自己的根节点，路由限于 `#/theme/pixel/accounts`、`#/theme/pixel/more`、`#/theme/pixel/preferences`。主机弹窗、认证、OAuth、快速 OTP、扩展接口和 PWA 生命周期仍由主机管理。

构建包还包含可选的 `public-appearance.json`：新主机可在登录/独立公共页面使用有限静态配色与已声明的字体，无需运行主题脚本；旧主机可继续导入为普通文件。描述来自同一配色映射，明暗和已选主题设置保持一致。

新主机可选提供 `sdk.host.setAppearance(tokens)`，Pixel 按当前明暗、强调色与中文字体配置同步官方弹窗/提示的颜色、字体及直角硬阴影。这里只提交视觉参数，不保存业务数据；不重复读取 computed style，也不随每秒验证码订阅重复设置。未提供该方法的旧主机仍正常挂载，官方弹层使用原样式。主题启动完成后才由主机激活，卸载/失效时由主机撤销；隔离预览不会更改父页面弹窗。

卸载同步清理订阅、计时器、事件、显示过渡和主题节点，不销毁主机账户内核。已开始的系统剪贴板或服务器请求不能被主题声称取消，迟到结果仍由主机记录，旧界面不会复活。
